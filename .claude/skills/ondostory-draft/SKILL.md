# ondostory-draft

온도스토리 블로그 초안을 쓰는 스킬. 원천 규칙 전문은 [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md). 이 파일은 그 핵심을 작성 실행용으로 압축한 것.

## 🚫 절대 규칙 (넘지 말 것)
1. **발행 금지.** `status='draft'`, `published=false`로만 저장한다. 발행 버튼은 사람이 누른다. 어떤 경우에도 `status='published'`로 저장하지 않는다.
2. **경험·평가는 사용자만, 공개 사실은 검색해서 채운다.**
   - **경험·맛·느낌·솔직한 평가**는 사용자가 준 것만 쓴다. **절대 지어내지 않는다** (정직성 = E-E-A-T 자산).
   - **공개 사실**(위치·주소·시그니처/대표 메뉴·추천 메뉴 등)은 **웹 검색해서 찾아 채운다.** 예전 방식이 이거다. 검색해도 못 찾는 것만 `[[확인 필요: 무엇]]`.
   - **단, 불확실하면 안 쓴다.** 소스마다 값이 다르거나 자주 바뀌는 것(**특히 영업시간**)은 신뢰할 소스 하나로 확정 안 되면 **확정적으로 적지 말고 생략**한다(disclaimer가 커버). 위치·주소처럼 안정적인 것 위주로.
3. **가격은 조심해서.** 찾으면 써도 되지만:
   - 배달앱(UberEats·DoorDash·Caviar 등) 가격은 **마크업이라 실제 매장가와 다르다 → 쓰지 않는다.** 공식 사이트/실제 매장 기준만.
   - 확실치 않으면 **생략**한다.
   - 가격·메뉴 등 공개정보를 쓰면, **글 맨 아래에 disclaimer 문장을 반드시** 넣는다(기존 글 표준 문구, 내용 맞춤):
     `<blockquote><p>이 글은 내가 직접 방문한 경험을 바탕으로 적은 것이다. 메뉴·가격·혼잡도는 시기에 따라 바뀔 수 있으니, 방문 전 확인하길 권한다.</p></blockquote>`
   - **그 글에서 실제로 바뀌는 것들을 콕 집는다** (맛집=메뉴·가격·혼잡도 / 자동차=가격·워런티·점검결과 / 은행=서류·크레딧 조건 등). 두루뭉술한 "…등"만 쓰지 않는다. 끝맺음은 "권한다"가 표준.
4. **사진은 사람이 채운다. 최대 2장.** `[사진: 무엇을 보여줄지]` 마커는 **최대 2개**만. 마땅한 자리가 애매하면 **맨 위 메인 1장**만. cover_image는 null(사람이 채움).
   - **커버가 마땅찮으면**(명함·영수증뿐) 사람이 관련 무료 스톡을 커버로, 실물은 본문에 — 마커에 `[사진: (커버는 관련 스톡, 명함은 여기)]`처럼 안내.
   - **사진을 잃어버렸으면 글에 솔직히 적는다**("전후 사진 찍어뒀는데 못 찾겠다, 아쉽다") — 사람 티 나는 진정성 신호.
5. **슬러그는 5단어 조합.** 영문 소문자·하이픈, 키워드 중심 5단어(예: `irvine-hako-tonkatsu-restaurant-review`). 단 **최종 확정은 발행 시점에 사람이** 한다(확정 후 불변).

## 입력 받기
사용자가 글감을 충분히 안 줬으면 먼저 물어본다: 무슨 경험인지, 장소/제품명, 좋았던 점, **솔직한 단점**, 가격·구체 정보, **(업체·병원·정비면) 한국어 되는지/한국분 운영인지**, 누구에게 도움 될지. 이게 있어야 B 보이스가 나온다.

**한인 독자 맞춤 정보:** OC 한인 타깃이라 **"한국어 되는 곳인가"**가 은근히 중요한 실용 정보(영어로 서비스 설명 부담). 병원·정비·업체 후기에서 **사실이면** 본문에 자연스럽게 + `정리하면`에 `한국어: 가능(한국분 운영)` 식으로 넣는다.

## 보이스 (B 표준 — DMV 삽질기 톤)
- **평서체 반말 문어체**: `~했다 / ~이다 / ~한다`. 존댓말(`~습니다`) 금지.
- **1인칭 "나/내"**, 아내는 "와이프", 가족은 "아이들". 아빠 시점. 캐주얼 구어("삽질", "허무했다") 허용.
- 짧게 끊어 쓴다. 한 문단 2~4문장.
- **결론부터** 던지고 상세는 뒤에. 도입부에 "이 글 왜 쓰는지"를 독자 배려로 밝힌다.
- **단점을 솔직하게 최소 1개.** 무조건 칭찬 금지.
- 과장·자극적 낚시 금지. 실제 겪은 감정만.
- **관계·경력을 과장하지 않는다.** 주인과 아는 사이가 아니면 "단골" 금지 — 실제론 자주 갈 뿐이니 "자주 찾는 곳 / 즐겨 찾는 / 몇 번을 다시 찾게 된 집"처럼 **일방적 빈도만** 담는다. (있지도 않은 관계 있는 척 X)

## 구조 (HTML로 작성 — 에디터가 tiptap HTML을 씀)
**글 유형에 따라 다르다.** 여기서 "사람 느낌 vs AI 느낌"이 갈린다. (상세: [운영 가이드 §2](../../../docs/ondostory-content-guide.md))

**후기(review) — 충분히 길게 + 문장형 소제목으로 조직화, 끝은 "정리하면" 블록.** (모찌·하코·쿠쿠 글 기준)
```
<p>[도입 — 상황 + 결론 살짝 + 왜 쓰는지]</p>
<p>[사진: 메인 이미지 — 사람이 넣음]</p>
<h2>[문장형 소제목: 한 주제 (자리·메뉴·맛·양·분위기 등)]</h2>
<p>[그 주제를 2~4문장으로 충분히 풀어씀. 맥락·감각·망설임 붙여 흐르게.]</p>
<p>[필요하면 같은 주제에 문단 하나 더.]</p>
<h2>[다음 주제 소제목]</h2>
<p>...</p>
... (주제마다: 문장형 소제목 + 실속 있는 문단 2~3개. 사진 [사진: ] 최대 2)
<h2>정리하면</h2>
<ul>
  <li><p><strong>위치</strong>: 4790 Irvine Blvd, Suite 103, Irvine (자이언마켓 바로 옆)</p></li>
  <li><p><strong>추천 메뉴</strong>: 하코 돈까스(대표 메뉴), 치즈 돈까스(모짜렐라가 들어간 속), 여름엔 자루소바</p></li>
  <li><p><strong>대기</strong>: 시간대에 따라 웨이팅 있음 → 붐빌 땐 to-go(포장) 추천</p></li>
  <li><p><strong>가격</strong>: 하코 돈까스 $14.95, 치즈 돈까스 $16.95 (가격은 시기에 따라 다를 수 있음)</p></li>
</ul>
<p>[독자용 추천 한두 문장]</p>
<blockquote><p>이 글은 내가 직접 방문한 경험을 바탕으로 적은 것이다. 메뉴·가격·혼잡도는 시기에 따라 바뀔 수 있으니, 방문 전 확인하길 권한다.</p></blockquote>
```
- 끝의 `정리하면` 블록은 기존 글 표준 포맷 — 각 항목은 **`<li><p><strong>라벨</strong>: 값</p></li>`**(라벨 볼드). 라벨은 위치/추천 메뉴/대기/가격 등 내용에 맞게. 본문 쪼개는 소제목이 아니라 맨 끝 요약 1개. **불확실한 영업시간 등은 넣지 않는다**.
- **가격 줄**: 확인된 메뉴 가격을 구체적으로(`하코 돈까스 $14.95, 치즈 돈까스 $16.95`) 넣고 줄 끝에 인라인 `(가격은 시기에 따라 다를 수 있음)`. 지명은 한글 표기 허용(`자이언마켓`).
- disclaimer는 맨 끝에 **`<blockquote>`로 감싼다**(세로바+회색). 그 글에서 실제 바뀌는 것 콕 집어(맛집=메뉴·가격·혼잡도). `※`·`<em>` 대신 blockquote.

**정보(how-to) — 구조 OK.** (DMV 글 기준) 단계별 **문장형** 소제목(`<h2>`) + 필요시 `<ol>` 번호 리스트.

공통:
- **소제목은 "말하듯 이어지는 문장"으로** (라벨—부연 템플릿 금지). 예: `흑임자 빙수 — 많이 안 달고 부드럽다`, `자리는 생각보다 있는 편, 다만 주말엔 다르다`.
- **소제목 자체는 문제 없다 — AI 티는 "얇은 섹션을 잘게 쪼갤 때" 난다.** 소제목 하나마다 **실속 있는 문단 2~3개(각 2~4문장)**를 붙여라. 1~2문장짜리 섹션을 소제목으로 쪼개면 초라해진다. (충분히 못 풀면 소제목을 합쳐라.)
- **단답 나열 금지.** 받은 사실 하나를 맥락·감각·망설임 붙여 여러 문장으로 푼다. 본문 **최소 2,000자 지향** (얇으면 덜 푼 것).
- 경험은 사용자 것만, 공개 사실(위치·영업시간·메뉴 등)은 검색해서 채운다(절대규칙 2). 검색해도 없으면 `[[확인 필요]]`.

## 산출 필드 (posts 스키마에 맞춤)
| 필드 | 규칙 |
|---|---|
| `title` | 키워드 앞쪽. 실용형=`대상 후기 \| 키워드 부제`, 후킹형=`대상 후기 – 서사 부제` 또는 괄호. |
| `slug` | 영문 소문자·하이픈, **키워드 중심 5단어 조합** (예: `irvine-hako-tonkatsu-restaurant-review`). 후보 제안(발행 시 사람이 확정). |
| `excerpt` | 요약 140~160자. 타깃 키워드 + 이 글이 답하는 것 + 실경험 신호 + 클릭 유도 1문장. 본문 첫 문장 복붙 금지. 목록 카드 미리보기로도 쓰임. |
| `content` | 위 HTML 구조. 사진 마커 최대 2개. 가격/영업시간 넣으면 하단 disclaimer 필수(절대규칙 3). |
| `tags` | 4~6개. **공백 표기(하이픈 금지)**. `[지역] + [대상/브랜드] + [행위/카테고리] + [롱테일]`. 한글 우선, 영문 브랜드/지명 1~2개 허용. |
| `cluster` | 아래 6개 중 정확히 1개 (key). |
| `category` | `후기` 또는 `정보` 중 1개. |
| `meta_title` | **SEO 제목 작성** (비워두지 않음). 키워드 앞쪽, 60자 내외. |
| `meta_description` | **SEO 설명 작성** (비워두지 않음). 140~160자, 키워드 포함. excerpt와 별개로 채운다. |
| `cover_image` | null (사람이 실제 사진으로 채움). |

### cluster (key 1개 선택)
- `settlement` 🧭 정착 실무 — 은행·송금·DMV·자동차·병원
- `housing` 🏠 렌트·이사 — 아파트/하우스 렌트, 이사, 디파짓
- `kids` 🎒 자녀교육·학교 — 학원, 백투스쿨, 학교 행정/검사
- `food` 🍽️ 맛집·집밥 — 맛집, 집밥, 주방 제품
- `travel` ✈️ 여행·나들이 — 여행지, 근교 나들이, 로컬 이벤트
- `shopping` 🛍️ 쇼핑·생활정보 — 세일, 중고거래, 생활 꿀팁
- 애매하면 가장 가까운 것. 정착 관련 얇은 주제(자동차/의료)는 `settlement`.

### category
- `후기` — "이거 살까/갈까?"에 답하는 특정 대상 경험 평가 (기본값)
- `정보` — "어떻게 하지?"에 답하는 방법·비교·리스트

## 저장 (Supabase에 draft로 insert)
Supabase MCP(`mcp__supabase__execute_sql`)로 저장한다. content의 작은따옴표는 이스케이프.
```sql
insert into posts (title, slug, content, excerpt, tags, cluster, category, meta_title, meta_description, status)
values (
  '제목',
  '다섯-단어-슬러그-조합-키워드',
  '<p>...</p>',
  '요약 140~160자',
  array['태그1','태그2','태그3','태그4'],
  'cluster_key',
  '후기',
  'SEO 제목 (60자 내외)',
  'SEO 설명 (140~160자)',
  'draft'
)
returning id, slug, status;
```
작은따옴표가 섞이면 dollar-quoting(`$body$...$body$`) 사용. `published`는 트리거가 status에서 자동 유도하니 넣지 않는다.
- `published`는 트리거가 status에서 자동 유도하므로 넣지 않는다.
- **`post_ideas`에서 생성한 경우: 초안 insert 성공 후 그 아이디어 row를 `delete` 한다** (status='done'로 두지 말고 삭제). 아이디어 목록엔 "아직 글 안 쓴 것"만 남아야 뭘 안 썼는지 한눈에 보인다.
- 저장 후 사용자에게 알린다: draft 저장됨, 관리자(`/admin`)에서 검토 → 사진 넣고 → 발행. `[[확인 필요]]`와 `[사진: ]` 마커 목록을 함께 보여줘 사람이 뭘 채워야 하는지 명확히 한다.

## 저장 후 체크리스트로 자기검증
[docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md) 9번 발행 전 체크리스트를 스스로 돌려본다:
제목 키워드 앞쪽 / 도입 후크 / 소제목 구조 / 번호 리스트 정리 / 솔직한 단점 1개 / 구체 정보(또는 확인필요 마커) / 요약 140~160자 / 태그 4~6개 공백 / 클러스터 지정 / 카테고리 후기·정보 / 슬러그는 후보.
