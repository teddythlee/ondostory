# ondostory-draft

온도스토리 블로그 초안을 쓰는 스킬. 원천 규칙 전문은 [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md). 이 파일은 그 핵심을 작성 실행용으로 압축한 것.

## 🚫 절대 규칙 (넘지 말 것)
1. **발행 금지.** `status='draft'`, `published=false`로만 저장한다. 발행 버튼은 사람이 누른다. 어떤 경우에도 `status='published'`로 저장하지 않는다.
2. **경험을 지어내지 않는다.** 사용자가 준 사실·경험만 쓴다. 모르는 구체값(가격·날짜·주소·모델명·소요시간 등)은 지어내지 말고 `[[확인 필요: 무엇]]` 플레이스홀더로 남긴다. 정직성이 이 블로그의 SEO 자산(E-E-A-T)이다.
3. **사진은 사람이 채운다.** 직접 찍은 사진 자리에 `[사진: 무엇을 보여줄지]` 마커를 넣는다. 이미지를 임의로 삽입하지 않는다(cover_image는 null로 둔다).
4. **슬러그는 제안만.** 최종 확정은 발행 시점에 사람이 한다(확정 후 불변 규칙 때문). 초안 슬러그는 후보일 뿐임을 명시한다.

## 입력 받기
사용자가 글감을 충분히 안 줬으면 먼저 물어본다: 무슨 경험인지, 장소/제품명, 좋았던 점, **솔직한 단점**, 가격·구체 정보, 누구에게 도움 될지. 이게 있어야 B 보이스가 나온다.

## 보이스 (B 표준 — DMV 삽질기 톤)
- **평서체 반말 문어체**: `~했다 / ~이다 / ~한다`. 존댓말(`~습니다`) 금지.
- **1인칭 "나/내"**, 아내는 "와이프", 가족은 "아이들". 아빠 시점. 캐주얼 구어("삽질", "허무했다") 허용.
- 짧게 끊어 쓴다. 한 문단 2~4문장.
- **결론부터** 던지고 상세는 뒤에. 도입부에 "이 글 왜 쓰는지"를 독자 배려로 밝힌다.
- **단점을 솔직하게 최소 1개.** 무조건 칭찬 금지.
- 과장·자극적 낚시 금지. 실제 겪은 감정만.

## 구조 (HTML로 작성 — 에디터가 tiptap HTML을 씀)
```
<p>[도입 후크 — 상황 + 결론 살짝 + 왜 쓰는지]</p>
<h2>[소제목1: 배경/발단]</h2>
<p>...</p>
<p>[사진: ...]</p>
<h2>[소제목2: 과정/문제]</h2>
...
<h2>정리</h2>
<ol><li>...</li><li>...</li></ol>
<p>[마무리 — 한 문장 교훈 + 독자용 추천]</p>
```
- **소제목(`<h2>`)으로 반드시 구조화.** 줄글 금지.
- 핵심은 **번호 리스트(`<ol>`)로** 한 번 더 정리.
- 분량 본문 1,500~2,500자(정보 많으면 3,000자+).
- 구체 정보(가격·모델명·지명·절차)를 넣되, 없으면 `[[확인 필요]]`.

## 산출 필드 (posts 스키마에 맞춤)
| 필드 | 규칙 |
|---|---|
| `title` | 키워드 앞쪽. 실용형=`대상 후기 \| 키워드 부제`, 후킹형=`대상 후기 – 서사 부제` 또는 괄호. |
| `slug` | 영문 소문자, 하이픈. **후보 제안일 뿐**(발행 시 확정). |
| `excerpt` | **= 메타 디스크립션. 140~160자.** 타깃 키워드 + 이 글이 답하는 것 + 실경험 신호 + 클릭 유도 1문장. 본문 첫 문장 복붙 금지. 목록 카드 미리보기로도 쓰이니 매력적으로. |
| `content` | 위 HTML 구조. |
| `tags` | 4~6개. **공백 표기(하이픈 금지)**. `[지역] + [대상/브랜드] + [행위/카테고리] + [롱테일]`. 한글 우선, 영문 브랜드/지명 1~2개 허용. |
| `cluster` | 아래 6개 중 정확히 1개 (key). |
| `category` | `후기` 또는 `정보` 중 1개. |
| `meta_title`, `meta_description` | 보통 null (제목/요약이 폴백됨). 특수 케이스만 채움. |
| `cover_image` | null (사람이 실제 사진으로 채움). |

### cluster (key 1개 선택)
- `settlement` 🧭 정착 실무 — 은행·송금·DMV·자동차·병원
- `housing` 🏠 렌트·이사 — 아파트/하우스 렌트, 이사, 디파짓
- `kids` 🎒 자녀교육·학교 — 학원, 백투스쿨, 학교 행정/검사
- `food` 🍽️ 맛집·집밥 — 맛집, 집밥, 주방 제품
- `travel` ✈️ 여행·나들이 — 여행지, 근교 나들이, 로컬 이벤트
- `shopping` 🛍️ 쇼핑·생활정보 — 세일, 중고거래, 생활 꿀팁
- 애매하면 가장 가까운 것. 정착 관련 얇은 주제(자동차/의료)는 `settlement`.

### category
- `후기` — "이거 살까/갈까?"에 답하는 특정 대상 경험 평가 (기본값)
- `정보` — "어떻게 하지?"에 답하는 방법·비교·리스트

## 저장 (Supabase에 draft로 insert)
Supabase MCP(`mcp__supabase__execute_sql`)로 저장한다. content의 작은따옴표는 이스케이프.
```sql
insert into posts (title, slug, content, excerpt, tags, cluster, category, status)
values (
  '제목',
  '제안-슬러그',
  '<p>...</p>',
  '요약 140~160자',
  array['태그1','태그2','태그3','태그4'],
  'cluster_key',
  '후기',
  'draft'
)
returning id, slug, status;
```
- `published`는 트리거가 status에서 자동 유도하므로 넣지 않는다.
- 저장 후 사용자에게 알린다: draft 저장됨, 관리자(`/admin`)에서 검토 → 사진 넣고 → 발행. `[[확인 필요]]`와 `[사진: ]` 마커 목록을 함께 보여줘 사람이 뭘 채워야 하는지 명확히 한다.

## 저장 후 체크리스트로 자기검증
[docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md) 9번 발행 전 체크리스트를 스스로 돌려본다:
제목 키워드 앞쪽 / 도입 후크 / 소제목 구조 / 번호 리스트 정리 / 솔직한 단점 1개 / 구체 정보(또는 확인필요 마커) / 요약 140~160자 / 태그 4~6개 공백 / 클러스터 지정 / 카테고리 후기·정보 / 슬러그는 후보.
