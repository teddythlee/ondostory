# ondostory-draft

온도스토리 블로그 초안 작성 스킬.

> **모든 글쓰기·SEO 규격의 단일 원본 = [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md).**
> 이 파일은 규격을 복사하지 않는다 — **작업 순서 + 절대 지켜야 할 가드레일 + 저장 방법**만 담는다.
> 규격(보이스·구조·제목·메타·태그·클러스터·카테고리·이미지·체크리스트)은 **매번 가이드를 읽어서** 따른다.
> 규격을 바꿀 일이 생기면 이 파일이 아니라 **가이드를 고친다.**

## 🎯 마인드셋
빨리 하나 뽑는 게 목표가 아니다. **한 편에 온 힘을 다해 "발행해도 될 최고 품질"로.** 속도 < 품질.
기준선 = 발행된 `irvine-mochi-dessert-cafe-review`, `buena-park-auto-glass-repair-review`. 그 밀도·흐름에 못 미치면 아직 덜 된 것.

## 작업 순서 (이대로)
1. **가이드를 읽는다** — [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md). 보이스(§1)·구조(§2)·편집 심화(§2.5)·제목(§3)·메타(§4)·태그(§5)·클러스터(§6)·카테고리(§7)·이미지(§8)·체크리스트(§9)가 전부 여기 있다.
2. **기존 발행글 2~3개를 읽는다**(위 기준선 글 등) — 밀도·톤 감을 잡는다.
3. **입력을 받는다**(아래) — 부족하면 먼저 묻는다.
4. **[가드레일 확인]** 아래 🚫 절대 규칙을 점검한다.
5. 검색 의도 한 줄("이걸 누가, 어떤 말로 검색?") → 초안 작성(가이드 §1~2 규격) → **편집자 눈 자기검토**(가이드 §2.5) → 산출 필드 채우기.
6. **draft로 저장**(아래 SQL). 발행은 사람이 한다.

## 🚫 절대 규칙 (가드레일 — 절대 넘지 말 것)
1. **발행 금지.** `status='draft'`로만 저장한다. 어떤 경우에도 `status='published'`로 저장하지 않는다. 발행 버튼은 사람이 누른다.
2. **경험·평가는 사용자 것만, 지어내지 않는다**(정직성 = E-E-A-T 자산). 맛·느낌·솔직한 평가는 사용자가 준 것만. 공개 사실(위치·주소·대표 메뉴 등)은 웹 검색해 채우되, **불확실하면(특히 영업시간) 확정적으로 쓰지 말고 생략**한다. 검색해도 못 찾은 것만 `[[확인 필요: 무엇]]`.
3. **가격은 조심.** 배달앱(UberEats·DoorDash 등) 마크업 가격 X — 공식/실제 매장가만. 불확실하면 생략. 가격·메뉴를 넣으면 **글 맨 끝 disclaimer 필수**(그 글에서 실제 바뀌는 걸 콕 집어):
   `<blockquote><p>이 글은 내가 직접 방문한 경험을 바탕으로 적은 것이다. 메뉴·가격·혼잡도는 시기에 따라 바뀔 수 있으니, 방문 전 확인하길 권한다.</p></blockquote>`
4. **사진 최대 2장.** `post_ideas.image_urls`가 있으면 `[사진:]` 마커 대신 실제 사진을 `<img class="rounded-lg" src="URL" width="50%">`로 본문에 배치(첫 사진은 cover_image로도). 가능하면 사진을 열어보고 사진에 맞는 묘사를 쓴다. 없으면 `[사진: 무엇을 보여줄지]` 마커 최대 2개 + cover_image=null. **사진을 잃어버렸으면 글에 솔직히 적는다**(진정성 신호). (저작권·EXIF·보정 방법은 가이드 §8.)
5. **슬러그 = 최대 5단어(3~5, 짧을수록 좋음), 영문 소문자·하이픈.** 후보만 제안하고 최종 확정은 발행 시점에 사람이 한다(확정 후 불변). **이미 배포된 글의 슬러그는 함부로 바꾸지 않는다** — 색인이 꼬이고 유입이 끊긴다. 불가피하면 `next.config.ts`에 301/308 리다이렉트를 반드시 건다.

## 입력 받기
글감이 부족하면 먼저 묻는다: 무슨 경험인지, 장소/제품명, 좋았던 점, **솔직한 단점**, 가격·구체 정보, (업체·병원·정비면) **한국어 되는지/한국분 운영인지**, 누구에게 도움 될지. (한인 독자 맞춤 정보는 가이드 §1 참조.)

## 산출 필드 (규격은 가이드 참조 — 여기선 목록만)
- `title`(§3) · `slug`(절대규칙 5 · §9) · `excerpt` 140~160자(§4, 빈 값 금지) · `content`(§2 HTML 구조)
- `tags` 4~6개 **공백 표기**(§5) · `cluster` = clusters 테이블의 key 1개(§6) · `category` = `후기`/`정보`(§7)
- `meta_title` 60자 내외 · `meta_description` 140~160자(둘 다 채운다) · `cover_image` = null(사람이 채움) 또는 image_urls 첫 장

## 저장 (Supabase에 draft로 insert)
`mcp__supabase__execute_sql`로 저장한다. content의 작은따옴표는 이스케이프(섞이면 dollar-quoting `$body$...$body$`).
```sql
insert into posts (title, slug, content, excerpt, tags, cluster, category, meta_title, meta_description, status)
values ('제목','다섯-단어-슬러그-조합','<p>...</p>','요약 140~160자',
  array['태그1','태그2','태그3','태그4'],'cluster_key','후기','SEO 제목(60자 내외)','SEO 설명(140~160자)','draft')
returning id, slug, status;
```
- `published`는 트리거가 status에서 자동 유도하니 넣지 않는다.
- **`post_ideas`에서 만든 경우: insert 성공 후 그 아이디어 row를 `delete`** 한다(status='done'로 두지 말고 삭제 — 목록엔 아직 안 쓴 것만 남긴다).
- 저장 후 알린다: draft 저장됨 → 관리자(`/admin`)에서 검토 → 사진 넣고 → 발행. `[[확인 필요]]`·`[사진:]` 마커 목록을 함께 보여준다.

## 저장 후 자기검증
가이드 §9 발행 전 체크리스트를 스스로 돌려본다.
