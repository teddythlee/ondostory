# ondostory-blog

온도스토리 블로그 리서치·초안 스킬.

> **모든 글쓰기·SEO 규격의 단일 원본 = [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md).**
> 이 파일은 규격을 복사하지 않는다 — **작업 순서 + 절대 가드레일 + 저장 방법**만 담는다.
> 규격(보이스·구조·제목·메타·태그·클러스터·카테고리·이미지·체크리스트·주제발굴·인제스트)은 **매번 가이드를 읽어** 따른다. 규격을 바꿀 일이 생기면 이 파일이 아니라 **가이드를 고친다.**

## 도구 이식성 (Claude ↔ Gemini 동일 품질)
품질은 **가이드 + 이 폴더의 prompt 파일**에서 나온다. 두 도구가 같은 결과를 내는 방법:
- **Gemini**: `docs/ondostory-content-guide.md`와 해당 단계 `prompts/*.md`를 붙여넣고 그대로 따르게 한다. 최종 산출은 **editor-ready 블록**(아래)으로 받아 사람이 `/admin`에 넣는다.
- **Claude(여기)**: 위 파일들을 읽어 따르고, 추가로 **리서치 자동화(WebSearch + GSC)** 와 **draft 저장(`/api/drafts`)** 까지 수행한다.
- 두 도구 모두 **출력 언어는 한국어**, 규격 원본은 하나(가이드)라 품질이 갈리지 않는다.

## 🎯 마인드셋
빨리 하나 뽑는 게 목표가 아니다. **발행해도 될 최고 품질의 초안**을 목표로 한다. 속도 < 품질.
초안은 완성이 아니라 **사람이 실제 경험을 얹을 골격**이다 — 지어내서 채우지 말고, 경험이 들어갈 자리를 명확히 비워 둔다.

## 작업 순서 (필요한 단계만)
요청이 좁으면 불필요한 단계는 건너뛴다. 무엇을 원하는지 먼저 판별한다: 주제 발굴 / 주제 비교 / 아웃라인 / 신규 초안 / 리라이트 / SEO 점검 / 발행 패키지.

1. **가이드를 읽는다** — [docs/ondostory-content-guide.md](../../../docs/ondostory-content-guide.md). 보이스(§1)·구조(§2)·편집 심화(§2.5)·제목(§3)·메타(§4)·태그(§5)·클러스터(§6)·내부링크(§6.5)·카테고리(§7)·이미지(§8)·체크리스트(§9)·주제발굴(§12)·인제스트(§13)가 전부 여기 있다.
2. **리서치 & 주제 발굴** — `prompts/research.md`. 검색량은 있는데 경쟁이 약한 **롱테일** 후보를 찾고, GSC 신호(`lib/gsc.ts`·`/api/gsc`)와 `data/content-history.json`·기존 발행글로 **중복을 피하며** 점수표로 고른다.
3. **기획** — `prompts/planning.md`. 독자·검색 의도·핵심 질문·고유 가치·근거·아웃라인·CTA를 한 줄씩 정한다.
4. **작성** — `prompts/writing.md` + 가이드 §1~2. 리서치 기반 초안을 쓰되, **경험이 필요한 자리는 `[[경험 추가: 무엇]]`으로 비워 둔다**(지어내지 않는다).
5. **SEO** — `prompts/seo.md` + 아래 **🔎 SEO·검색어·구조 체크**를 실제로 돌린다. 제목·슬러그·메타·태그·클러스터·내부링크(검증된 것만)·FAQ·alt를 채운다.
6. **리뷰(검수)** — `prompts/review.md` + 가이드 §2.5·§9. 편집자 눈으로 사실 공백·근거 없는 주장·반복·어색한 한국어·AI 상투어를 걷어낸다. **⚠️ 검수 시 "발행/감사 QA 전수 스캔" 필수**(신규 초안뿐 아니라 **기존 글 보강·SEO 점검·사이트 감사** 때도 매번). 발행본에 이런 잔해가 남으면 독자 눈에 그대로 보이고 AdSense가 "미완성/저품질"로 잡는다. 아래 한 쿼리로 전수 검사한다 —
```sql
select slug,
  (content ~ '\[(사진|AI 일러스트|경험 추가|확인 필요)') as marker,          -- [사진:]·[AI 일러스트:]·[[경험/확인]]
  (content ~ 'alt="[^"]*이미지 [0-9]' or content like '%ondostory 이미지%'
     or content like '%alt=""%') as bad_alt,                             -- 자동 placeholder alt·빈 alt
  (content ~ '[0-9]{4}년 [0-9]{1,2}월 [0-9]{1,2}일까지') as hardcoded_date, -- 지난 만료일 박제(→ 눈으로 지났는지)
  ((content ~* '\$[0-9]|[0-9]+ *불') and content not like '%<blockquote>%') as price_no_disclaimer
from posts where status='published' and (
  content ~ '\[(사진|AI 일러스트|경험 추가|확인 필요)'
  or content ~ 'alt="[^"]*이미지 [0-9]' or content like '%ondostory 이미지%' or content like '%alt=""%'
  or content ~ '[0-9]{4}년 [0-9]{1,2}월 [0-9]{1,2}일까지'
  or ((content ~* '\$[0-9]|[0-9]+ *불') and content not like '%<blockquote>%'));
```
   - **마커**는 실제 사진·경험이 있어야 채워지므로 임의로 채우지 말고 **채우거나 지운다.** (`[AI 일러스트: …]`도 §8-4가 커버로 권장 → placeholder가 생기니 반드시 스캔 대상.)
   - **표**는 `<p>`에 셀이 뭉치지 않고 실제 `<table>`인지 눈으로 확인(자동 탐지는 오탐 많아 쿼리에 안 넣음 — 중고거래 글이 셀 뭉친 채 발행된 적 있음).
   - **disclaimer**는 일반 `<p>`·리스트 `<em>`이 아니라 실제 `<blockquote>`인지 확인.
   - **발행글을 SQL로 고쳤으면 곧바로 `POST https://www.ondostory.com/api/revalidate`**(Bearer `DRAFT_API_TOKEN`, body `{"slugs":[...]}`)로 즉시 반영 — 안 하면 ~10분 ISR stale이라 그 사이 GSC가 옛 버전을 크롤한다.
7. **저장(draft)** — 아래. 발행은 사람이 한다.
8. **히스토리** — 실제 발행된 뒤에만 `data/content-history.json`을 갱신한다(초안은 사용자가 추적을 요청할 때만 `status:"draft"`로).

## 🔎 SEO·검색어·구조 체크 (작성·SEO 점검·검수마다 실제로 돌린다)
"SEO 관점으로 봐줘"를 스스로 돌리는 체크리스트. 형식 규격은 가이드(§2 구조·§3 제목·§4 메타·§5 태그·§6.5 내부링크), 여기선 **꼭 확인할 항목**만.

**A. 검색어 — 정하고, 눈에 띄는 자리에 심는다**
- 이 글이 노릴 **메인 검색어 1~2개 + 롱테일 몇 개**를 먼저 정한다(사람들이 실제 치는 말. 추정 말고 GSC·자동완성 신호로). 브랜드/업체명 단독어는 못 이기니 스킵([[branded]] 원칙).
- **제목 앞 10~12자**(가중치 최대)에 메인 검색어가 들어갔나 — 첫머리가 "미국·한국 오갈 때 뭘…" 처럼 질의어 없이 시작하면 **최우선 수정**. 클릭 유인 문구("교민이 실제 사는 것" 등)는 그 뒤에.
- **첫 문단 첫 100자**에 메인 키워드 1회.
- **H2·H3 소제목에 검색어.** "미국 → 한국" 같은 **화살표·기호는 검색 매칭 안 됨** → "미국에서 한국 갈 때 사갈 것"처럼 질의어로 바꾼다.
- meta_title·meta_description·태그·이미지 alt에도 자연스럽게(스터핑 금지, 각 1~2회).

**B. 구조 — 스캔되고, 구글 목차가 잡히게**
- 소제목은 **굵은 텍스트(`<strong>`)가 아니라 실제 `<h2>`/`<h3>`** 태그여야 한다. 굵은 글씨만 쓰면 문서 구조상 존재하지 않아 롱테일("50대 부모님 미국 선물")·목차 생성 자리를 통째로 버린다. 연령대·항목별 하위 구획은 **H3로 승격**.
- 벽 같은 산문 금지 — 짧은 문단 + **비교·규정·항목은 표(`<table>`)**로(스니펫 획득 기회). 그 글에서 제일 유니크한 정보를 산문에 묻지 말 것.
- 실제 검색되는 **롱테일 질문**(예: "영양제 몇 병까지?", "불닭 미국 반입?")은 **FAQ 블록**으로 빼면 별도 노출 기회가 생긴다. **제목은 `<h2>자주 묻는 질문</h2>`으로 통일**(영어 "FAQ" 혼용 금지 — 보이스·탐지 일관성). 질문은 `<h3>`, 답은 **본문에 이미 있는 내용만** 재구성(지어내지 말 것).
- 마지막 "정리하면" 요약.

**C. 링크 — 두 종류 다 (지금 0개면 손실)**
- **외부 1차 출처 링크**: 규정·데이터·수치는 공식 사이트(관세청 customs.go.kr·cbp.gov·aphis.usda.gov 등)를 **텍스트 언급이 아니라 실제 `<a>` 링크**로 — 신뢰도 신호.
- **내부 링크 2~3개를 본문 중간에.** 하단 자동 링크만으론 클러스터가 안 산다. 대상 슬러그 확인된 것만(§6.5).

**D. 이미지·분량**
- alt는 **한국어 키워드**로. 영문 스톡 캡션("The stylish departure board at JFK…")을 그대로 두지 말 것. **관리자 자동 placeholder alt(`이미지 1`·`ondostory 이미지 1`·제목 통째 dump)도 금지** — 그 이미지가 뭘 보여주는지 설명형 한국어로 교체(빈 `alt=""`도 금지).
- 리스트·롱폼은 2장으론 부족 — **섹션마다 1장**이면 자연히 keyword-rich alt가 여러 개 생긴다(사진 규격은 가드레일 5).
- 경쟁 키워드는 **2,000~3,000자** 지향(얇으면 저품질 신호). 단 패딩이 아니라 실제 정보(표·FAQ·출처)로 채운다.

## 🚫 절대 규칙 (가드레일 — 절대 넘지 말 것)
1. **발행 금지.** `draft`로만 저장한다. 어떤 경우에도 `published`로 저장하지 않는다. 발행 버튼은 사람이 누른다.
2. **경험·평가·사실을 지어내지 않는다**(정직성 = E-E-A-T 자산). 맛·느낌·솔직한 평가는 사용자가 준 것만. 공개 사실(위치·주소·대표 메뉴·절차 등)은 검색해 채우되, **불확실하면(특히 영업시간·가격) 확정적으로 쓰지 말고 생략**한다. 검색해도 못 찾은 것만 `[[확인 필요: 무엇]]`, 사용자 경험이 필요한 자리는 `[[경험 추가: 무엇]]`.
3. **추정 검색량을 측정값처럼 쓰지 않는다.** 실제 도구(GSC 등)가 준 숫자만 수치로 제시하고, 나머지는 "수요 신호(정성)"로만 표현한다.
4. **가격은 조심.** 배달앱 마크업 가격 X — 공식/실제 매장가만. 불확실하면 생략. 가격·메뉴를 넣으면 **글 맨 끝 disclaimer 필수**(가이드 §2 하우스 포맷: `<blockquote><p>…</p></blockquote>`).
5. **사진 최대 2장.** 실제 사진이 없으면 `[사진: 무엇을 보여줄지]` 마커 최대 2개(img 태그 넣지 않음, cover_image=null). 저작권·처리·임베드는 가이드 §8.
6. **슬러그 = kebab-case, 6단어 이하(짧을수록 좋음), 영문 소문자·숫자·하이픈.** 후보만 제안하고 최종 확정은 사람이. **이미 배포된 슬러그는 함부로 바꾸지 않는다**(색인·유입이 끊긴다). 불가피하면 리다이렉트를 건다.
7. **없는 걸 만들었다고 말하지 않는다.** 파일·검증·내부 링크는 실제로 확인한 것만. 내부 링크는 대상 슬러그를 확인한 경우에만 추천한다(§6.5).
8. **발행본에 마커가 남으면 안 된다.** `[사진: …]`·`[AI 일러스트: …]`·`[[경험 추가: …]]`·`[[확인 필요: …]]`는 **초안 전용** 표시다. 발행·감사·보강 시 전수 QA 스캔으로 마커 0을 확인한다(6번 검수 참조 — placeholder alt·빈 alt·지난 만료일·blockquote 없는 disclaimer도 함께). 남았으면 채우거나 지운 뒤에만 발행.

## 입력 받기
글감이 부족하면 먼저 묻는다: 무슨 경험/주제인지, 장소·제품·절차명, 좋았던 점, **솔직한 단점**, 가격·구체 정보, (업체·병원·정비면) **한국어 되는지/한국분 운영인지**, 누구에게 도움 될지. (한인 독자 맞춤은 가이드 §1.)

## 산출 필드 (규격은 가이드 참조 — 여기선 목록만)
- `title`(§3) · `slug`(가드레일 6·§9) · `excerpt` 140~160자(§4, 빈 값 금지) · `content`(§2 HTML 구조, 마크다운 X)
- `tags` 4~6개 **공백 표기**(§5) · `cluster` = clusters 테이블 key 1개(§6) · `category` = `후기`/`정보`(§7)
- `meta_title` 60자 내외 · `meta_description` 140~160자(**excerpt와 동일 금지** §4) · `cover_image` = null(사람이 채움) 또는 실제 사진 첫 장
- `social_hook`(선택) 스레드 훅 3줄, 200자 내외 — **답·결론을 주지 말고 궁금하게 여는 미끼**(요약 아님). 실제 경험에서만. 규칙·예시는 §13 하단

## 저장 (draft로만)

### Claude — `POST /api/drafts` (1차 경로, 권장)
가이드 §13의 정식 인제스트. **서버가 `status`를 무조건 draft로 강제**하고 슬러그·excerpt·태그·메타·disclaimer를 검증한다. 네트워크 열린 곳(여기)에서 호출한다.
```
POST https://www.ondostory.com/api/drafts
Authorization: Bearer <DRAFT_API_TOKEN>   # wrangler 시크릿
Content-Type: application/json
{ "title","slug","content"(HTML),"excerpt","tags"[],"cluster","category","meta_title","meta_description","social_hook"(선택) }
```
성공 시 `201 {ok,id,slug,status:"draft",admin_url}` → `/admin/drafts`에 뜬다. 검증 규칙·필수 필드는 가이드 §13 참조.

**폴백(엔드포인트 불가 시)**: `mcp__supabase__execute_sql`로 `posts`에 `status='draft'` 직접 insert(작은따옴표 이스케이프, 필요시 `$body$…$body$`). `published`는 트리거가 유도하니 넣지 않는다.

### Gemini — editor-ready 블록
DB 저장 없이 아래를 출력하고, 사람이 `/admin`에 붙여넣는다:

draft 저장됨 → 관리자(`/admin/drafts`)에서 검토 → **내가 읽으며 `[[경험 추가]]` 자리를 채우고** → 사진 넣고 → 내부 링크 확인(§6.5) → 발행. `[[확인 필요]]`·`[[경험 추가]]`·`[사진:]` 마커 목록을 함께 보여준다. 마지막으로 가이드 §9 발행 전 체크리스트를 스스로 돌린다.
